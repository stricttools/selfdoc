## 0.43.0

The Go module moves to github.com/stricttools/selfdoc (install with go install github.com/stricttools/selfdoc@v0), and fixes for the defects a repository meets on its way off the old layout: a deleted generated page no longer leaves its hash-store entry behind, the layout and frontmatter refusals print a remedy the refused repository can run, the first refusal prints the whole ordered migration procedure, the move script resolves its selfdoc binary before it commits anything, a staleness finding names both ways out and accept says why it has nothing to do, check says in its own help that it writes and commits the baselines, and the skeleton-only coverage list names the page whose seeded description is the cause.

<details>
<summary>Context</summary>

Every fix carries a red-green regression test. The two maintenance scripts -- the layout move and the frontmatter converter -- live only in selfdoc's own repository and no release artifact carries them, so every refusal that names one now prints the commands that fetch it and then run it, rather than a scripts/ path the refused repository does not have.

</details>

### Breaking

- **The Go module is now `github.com/stricttools/selfdoc`.** Install with `go install github.com/stricttools/selfdoc@v0`; the old `github.com/smm-h/selfdoc` path serves no version from 0.43.0 on (earlier releases stay where they were published, which is why the layout migration still builds its pre-flip sitemap with `go run github.com/smm-h/selfdoc@v0.41.0 build`). The scripts a refusal tells you to fetch now live under the stricttools organization.

### Fixes

- `selfdoc gen` now removes a deleted generated page's entry from the hash baseline store instead of leaving it behind, so the store no longer accumulates entries for pages that are not on disk
- The refusals of the old repository layout and of a retired `---` frontmatter block now print a remedy the refused repository can run: the commands that fetch the maintenance script and then run it, instead of a `scripts/...` path that only exists in selfdoc's own checkout
- The layout move script no longer ends in a Python traceback after committing: it resolves the selfdoc binary the verifying build needs before it writes anything, taking `selfdoc` from PATH when `--selfdoc` names none, and refuses with an untouched repository when no binary can be found
- The refusal of the old repository layout now prints the whole ordered migration procedure -- the required `versions` and `locales` config keys, the frontmatter conversion including generated pages, the pre-flip build that captures the URL set, creating the tool-state directory, and the move itself -- instead of leaving each prerequisite to be discovered by running into the next refusal
- A STALE001 or DRIFT001 finding now says that editing the page description and running `selfdoc baseline accept` are alternatives rather than consecutive steps, and `baseline accept` explains that a rewritten description already cleared the finding instead of only reporting "nothing to accept"
- `selfdoc check` now says in its own help that it advances the staleness baseline store and commits it, so a run that looks like a read-only audit no longer surprises with a write; `--auto-commit` help also states the store is written whether or not it is committed
- The coverage report's skeleton-only list now names the generated pages whose still-seeded frontmatter descriptions are the cause and says the symbols' own doc comments are not, instead of listing symbols alone and sending readers to rewrite doc comments that were already complete
- **A dry run of the layout move no longer needs a selfdoc binary.** The dry run builds nothing, so it now prints which binary `--apply` would use for its verifying build, or that none was found, and still prints the whole plan; `--apply` refuses a missing binary before it writes anything, as before.
