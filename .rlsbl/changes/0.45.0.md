## 0.45.0

selfdoc's per-repository directories move to a visible stricttools/ root, with generated directories behind a dot, and 'selfdoc layout migrate' moves a repository onto it. Each project now owns its spelling vocabulary: stricttools/vocabulary/terms.toml (accepted words with meanings, rejected terms with reasons) and review.toml (pending words), edited with 'selfdoc vocabulary'. The spell check reads only selfdoc's built-in baseline and the project's terms.toml. The manifest moves to schema_version 2, which records the project's accepted words and rejected patterns; every reader refuses schema 1, 'selfdoc layout migrate' converts it, a deploy or documentation publish refuses a vocabulary that disagrees with another project's on the site, and the new 'selfdoc assembly republish-all' republishes every project in one pass.

<details>
<summary>Context</summary>

The spell check used to read a machine-wide accept list outside every repository, so the same committed docs could pass on one machine and fail on another. Its general vocabulary now ships inside selfdoc as the baseline, and each project's own words live in its repository. The projects on one site share readers, so the manifest now carries each project's vocabulary onto the site, where two projects that disagree about a word (one's rejected pattern covering a word the other, or the baseline, accepts) are refused.

Upgrading, in this order:
1. Move the assembly's deploy pin to this release. For the owner's assembly this release's post-release hook does it; any other assembly runs 'selfdoc assembly sync-workflow --pin-selfdoc <this version>' in a project whose selfdoc.json declares assembly.repo. Until step 3 is done, deploys into the site fail: the other projects' manifests on it are still schema_version 1.
2. In every project: run 'selfdoc layout migrate --dry-run', read the plan, then 'selfdoc layout migrate', which moves the directories off .stricttools/ (when the project is still there) and converts the manifests to schema_version 2, and commits. A repository on the older .selfdoc/ layout follows the ordered procedure selfdoc's refusal prints instead: it fetches and runs move-to-stricttools-layout.py (--dry-run first), which moves the repository onto stricttools/ and then runs 'selfdoc layout migrate' itself. Then run 'selfdoc check', and for each word SPELL001 flags that the project really uses, run 'selfdoc vocabulary accept <word> --meaning <text>' (fix the prose for a real misspelling), and regenerate the manifest with 'selfdoc gen' so it records the vocabulary.
3. Once, from local checkouts of every project on the roster: 'selfdoc assembly republish-all --home <home checkout> --repo <checkout> --repo <checkout> ...', with --dry-run first. It replaces every project's manifest on the site (and converts each post overlay there), and sends one deploy request.

### Breaking

- **Breaking: selfdoc's per-repository directories live under a visible `stricttools/`, with generated directories behind a dot.** `stricttools/docs/`, `posts/` and `vocabulary/` keep their names; the generated ones are `stricttools/.docs-state/` and `stricttools/.docs-cache/`. Every command refuses a repository still keeping selfdoc's directories under `.stricttools/` and names `selfdoc layout migrate`. `selfdoc layout validate` refuses a selfdoc directory whose leading dot disagrees with its side, and `selfdoc init` also grants `stricttools/vocabulary/`. The move script for the older `.selfdoc/` layout writes the new layout in one step.
- **Breaking: the spell check no longer reads `~/Projects/ark/spelling-accept.txt`.** `selfdoc check`, `selfdoc spell-corpus` and the blog editor accept only selfdoc's built-in baseline and the project's own `stricttools/vocabulary/terms.toml`, so the same committed docs get the same verdict on every machine; move each project's words into its `terms.toml`. The `spell-corpus` payload replaces `accept_list` and `accepted_terms` with `baseline_terms` and a per-project `accepted_terms`. A word both accepted and rejected is a hard error.
- **The manifest records the project's vocabulary.** `stricttools/.docs-state/manifest.json` (and `post-manifest.json`) move to `schema_version` 2, which carries every word `terms.toml` accepts with its aliases and every pattern it rejects with its kind. Every reader refuses a schema 1 manifest: in a project it names `selfdoc layout migrate`, which now converts the manifests (in the same commit as the move off `.stricttools/`, or on its own for a repository already on `stricttools/`); on the assembly it names the project and `selfdoc assembly republish-all`. The `.selfdoc/` move script runs `selfdoc layout migrate` before its verifying build.

### Features

- **New `selfdoc layout migrate`** moves a repository off `.stricttools/`: every directory whose manifest names selfdoc moves under `stricttools/` with its new name, the derived ignore file is written, selfdoc's block leaves `.stricttools/.gitignore` (the file and the directory go when nothing else is left; another tool's directories stay), `selfdoc.json` paths and the generated root files' headers are rewritten, an empty `stricttools/vocabulary/terms.toml` is written when the project has none, and the move is committed. `--dry-run` prints the plan; an already migrated, a partially migrated and a never-migrated tree are refused with what to do instead.
- **New project vocabulary.** `stricttools/vocabulary/terms.toml` holds accepted words with their meanings and rejected terms with a kind (`word`, `phrase`, `suffix`, `prefix`) and a reason; `stricttools/vocabulary/review.toml` holds proposed words awaiting review, which the spell check still reports. New commands `selfdoc vocabulary accept`, `reject`, `remove`, `approve` and `drop` edit them in sorted position, keeping comments. SPELL001 names the command that resolves each word, and the new VOCAB lints report an accepted word no page uses, a duplicate entry, an accepted word a rejected suffix or prefix covers, a rejected term in page prose, and an unsorted array.
- **The built-in vocabulary baseline now carries general technical vocabulary.** Around a thousand entries, each with a meaning: file formats, protocols, acronyms, programming and database terms, and third-party product, library, and service names (for example `UUID`, `symlink`, `pgBackRest`, `WebSocket`). Every project's spell check accepts them without listing them; a project's `stricttools/vocabulary/terms.toml` holds only the words specific to that project, and an entry that repeats a baseline word is reported by VOCAB002.
- **One vocabulary per site.** A full-scope `selfdoc assembly integrate` and `selfdoc blog publish-docs` refuse, before writing anything, a project whose rejected pattern covers a word another project on the site or selfdoc's baseline accepts, or whose accepted word another project's pattern covers. The refusal names both projects, the word, the pattern and the fix: narrow the pattern (`selfdoc vocabulary remove <pattern>`, then `selfdoc vocabulary reject <word> --kind word --reason <text>`) or remove the word (`selfdoc vocabulary remove <word>`).
- **`selfdoc assembly republish-all`** publishes every project on the roster again from local checkouts (`--home <checkout> --repo <checkout> ...`), the one-time step that replaces every manifest on the site with a schema 2 one. Before building anything it refuses checkouts not on the `stricttools/` layout or with an outdated or missing manifest, checkouts that are not the roster's projects exactly, a deploy workflow pinning an older selfdoc (naming `selfdoc assembly sync-workflow --pin-selfdoc <version>`), and every vocabulary conflict between projects, listed in one pass. It then builds each project, publishes each in its own commit (converting the project's post overlay on the site too), and sends one deploy request; `--dry-run` builds and checks and prints what it would publish.

### Fixes

- **A rejection that covers words of selfdoc's built-in baseline is refused with a fix that works.** `selfdoc vocabulary reject ish --kind suffix` used to tell the project to remove `treeish` from the baseline, which no project can do. It now lists every baseline word the pattern covers (`treeish`, `unpublish`) and names narrowing the pattern instead: reject the specific words meant, for example `selfdoc vocabulary reject youngish --kind word --reason <text>`. VOCAB003 likewise names only entries the project owns: narrowing the pattern for a baseline word, and removing the word or narrowing the pattern for a word the project accepts.
- **Scratch directories no longer become documentation.** A project's `experiments/` and `screenshots/` at its root hold throwaway probes, yet `selfdoc gen` wrote an API page for a Go package or a module found in them, and the `list-modules` directive, coverage, `selfdoc quality` and schema discovery counted them too. Every source walk now prunes both directories at the project root; a directory of the same name deeper down is still ordinary source.
