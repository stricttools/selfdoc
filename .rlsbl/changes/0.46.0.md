## 0.46.0

selfdoc's per-repository directories move from stricttools/ to the hidden .strictmetadata/, and 'selfdoc layout migrate' moves a repository onto it. Lint codes become kebab-case names; each lint becomes an option, set in .strictmetadata/options/docs.toml with the new 'selfdoc options set', which replaces lint_ignore and 'selfdoc check --ignore' (both removed); 'selfdoc options registry' prints the options registry selfdoc ships; and a finding's lint in 'selfdoc check --json' is under 'name', no longer 'code'. The _CLAUDE.md template now generates .claude/CLAUDE.md instead of a CLAUDE.md at the repository root. With strictcli 0.38.0 the --json envelope is interface_version 3, with an output member, and 'selfdoc help --json' replaces 'selfdoc --dump-schema'.

<summary>Context</summary>

Upgrading a project, in this order:
1. Run 'selfdoc layout migrate --dry-run', read the plan, then 'selfdoc layout migrate'. It moves selfdoc's directories off stricttools/ (or .stricttools/) onto .strictmetadata/, rewrites the selfdoc.json paths and the generated root files' headers, moves a CLAUDE.md an earlier selfdoc generated at the repository root to .claude/CLAUDE.md, and commits. In a Go module, then run 'rlsbl scaffold' for the stub go.mod in .claude/ that keeps the file out of the module zip.
2. A selfdoc.json still declaring lint_ignore is refused with the 'selfdoc options set' command for each lint it names: run those, then delete lint_ignore from selfdoc.json.
3. Anything reading 'selfdoc check --json' reads a finding's lint from 'name' instead of 'code', and matches the new lint names instead of the old codes.
4. Anything reading selfdoc's --json envelope accepts interface_version 3 and its output member, and anything that ran 'selfdoc --dump-schema' runs 'selfdoc help --json', which prints the help document on stdout and writes no file.

### Breaking

- **The per-repository root moves to `.strictmetadata/`.** Every directory selfdoc owns now lives under the hidden `.strictmetadata/` instead of `stricttools/`. Every command refuses a repository still keeping selfdoc's directories under `stricttools/` or `.stricttools/`, naming `selfdoc layout migrate`, which moves them, rewrites the `selfdoc.json` paths and the generated root files' headers, converts the manifests, and commits; it refuses a repository holding selfdoc's directories under both previous roots.
- **Lint codes become names.** Every lint code (`SEO001`, `POST003`, `VOCAB002`, and the rest) is replaced by a lowercase kebab-case name (`multiple-top-level-headings`, `malformed-post-date`, `duplicate-vocabulary-entry`, and so on) in the human output, the `name` field of the `selfdoc check --json` payload, error and help text, and the docs; the check guide's lint table lists every name.
- **`lint_ignore` and `selfdoc check --ignore` are removed.** A lint is turned down only through its option. A `selfdoc.json` still carrying `lint_ignore` is refused with the `selfdoc options set` command that writes the entry for each lint it names, retired codes included.
- **A lint's identifier is its `name`, no longer its `code`.** Each finding in the `selfdoc check --json` payload carries its lint under `name` (the declared payload schema says the same), the blog editor's analysis findings do too, and the check guide's lint table heads that column Name. Migration: read `name` wherever you read `code` from a lint finding.
- **Breaking: the `_CLAUDE.md` template generates `.claude/CLAUDE.md`, not a `CLAUDE.md` at the repository root.** Claude Code loads `.claude/CLAUDE.md` as it loads a root `CLAUDE.md`, and the output path is fixed, with no setting. `selfdoc gen` creates `.claude/`, refuses while a `CLAUDE.md` an earlier selfdoc generated sits at the repository root, and refuses any output path git ignores, naming the ignore file, its line, and a narrower rule (`.claude/settings.local.json` instead of `.claude/`, for example); `selfdoc check` reports the root file as the error lint `generated-claude-md-at-repository-root`. Migration: run `selfdoc layout migrate --dry-run`, then `selfdoc layout migrate`, which moves the generated `CLAUDE.md` to `.claude/CLAUDE.md` and commits, in the same step as the move off the `stricttools/` or `.stricttools/` layout for a repository still on one; in a Go module, then run `rlsbl scaffold` for the stub `go.mod` in `.claude/` that keeps the file out of the module zip.
- **The `--json` envelope is `interface_version` 3, and `selfdoc help --json` replaces `selfdoc --dump-schema`**, from strictcli 0.38.0. The envelope gains an `output` member after `payload` (`null` when a command wrote no answer text), and `--dump-schema` is refused, naming `selfdoc help --json`, which prints the help document with every payload schema on stdout and writes no file. The upgrade also brings strictcli's stricter parsing: a flag that is not repeatable is refused when given twice, and an integer value with a plus sign or leading zeros (`+30`, `030`) is refused. A consumer pinning `interface_version` 2 must be updated.

### Features

- **Directories strictspec owns pass `selfdoc layout validate`.** A directory under `.strictmetadata/` whose `manifest.toml` names `strictspec` (the shared `options/` and `upstream/` directories) is accepted without a `strictspec` executable on `PATH`: strictspec is a library every reading tool links, not a command.
- **Each lint is an option, and `selfdoc options set` writes its entry.** selfdoc ships an options registry declaring `selfdoc:<lint name>` for every lint (`error > warn > off` for an error lint, `warn > off` for a warning lint). `selfdoc check` and `selfdoc build` read `.strictmetadata/options/` through strictspec, refuse any entry strictspec refuses with its catalogued diagnostic, and run each lint at its entry's `current` value: `off` is not reported, `warn` is reported without failing the run. `selfdoc options set <id> --current <value> --ideal <value> --reason <text>` writes or updates one entry in `.strictmetadata/options/docs.toml`, creating the directory and its manifest naming strictspec when absent, after strictspec accepts the result.
- **`selfdoc options registry` prints selfdoc's options registry.** The read-only command prints the TOML registry selfdoc ships, one option per lint (`selfdoc:<lint name>`) with its subject, ranked values, default, scope, and description, in the shape of strictspec's built-in options-registry schema, so a tool that reads every tool's options, such as strictcode, learns selfdoc's rankings by running it. It needs no selfdoc project; with `--json` the same declarations are the payload.

### Fixes

- **The "Built with selfdoc" link points at `github.com/stricttools/selfdoc`.** Every generated page's footer names selfdoc's repository in the stricttools organization, and the dirstat install hint the quality check prints names `github.com/stricttools/dirstat`.
